# iPhone版（PWA）の導入と運用

## 納品URLと公開方法

GitHub Pagesの納品URLは `https://ta713ku-ops.github.io/local-attendance-pwa/` です。試験運用開始後は、GitHubアカウント名とリポジトリ名を変更せず、このURLを固定して運用します。

mainブランチへ公開用変更を反映すると、GitHub Pagesの配信版が自動更新される構成を前提とします。ドメイン、プロトコル、ポートを含むoriginを変更しないでください。別のURLへ移すと、ホーム画面アプリとIndexedDBの保存領域が別物として扱われ、既存データをそのまま参照できません。

## 初回導入

1. 上記の **固定HTTPS URL** を、対象iPhoneのSafariで開きます。
2. 共有ボタンから「ホーム画面に追加」を選び、「追加」します。
3. 以後はホーム画面の「ローカル勤怠」アイコンから開いてください。初回に必要な画面を読み込めていれば、通常の打刻はオフラインでも利用できます。

Safari以外のブラウザや、URLを直接開いたままの利用では、ホーム画面アプリとしての動作・オフライン利用を確認できません。

## 保存場所と注意

勤怠データ、従業員情報、時給、設定、操作ログは、このiPhoneのIndexedDBだけに保存されます。GitHub Pagesはアプリ本体を配信しますが、業務データを保存・同期しません。ただし、iPhoneの初期化、SafariのWebサイトデータ削除、端末の故障・紛失で失う可能性があります。

管理者はアプリのバックアップ機能で定期的にバックアップを作成し、**別の安全な保管先**へ移してください。復元は、同じアプリ・同じ保存形式を使う端末で行います。

## 更新方法

更新版を配信するときは、必ず初回導入時と **同じHTTPSのorigin（ドメイン、プロトコル、ポート）** で公開してください。originが変わると、iPhoneは別アプリ・別の保存領域として扱います。

1. 更新前に管理画面からJSONバックアップを書き出し、iPhone外の安全な場所へ移します。
2. 公開用変更をmainブランチへ反映し、GitHub Pagesの自動更新が完了するまで待ちます。
3. iPhoneをネット接続し、ホーム画面のアプリを開きます。
4. 「新しいバージョンがあります」と表示されたら、打刻操作中でないことを確認して「今すぐ更新」を押します。打刻中は「あとで」を選べます。通知は操作を中断しません。
5. 更新後に画面が再読み込みされ、新しい版で起動することを確認します。

更新前にもバックアップを作成してください。オフライン中は既に保存済みの版を使い続け、ネット接続後の次回起動時に更新を取得します。

## 更新後のオフライン試験

実店舗で使い始める前と各更新後に、対象iPhoneのホーム画面アプリで次を確認します。

1. ネット接続中に固定URLからアプリを一度起動し、更新を完了します。
2. アプリを終了して機内モードにします。Wi-Fiも切れていることを確認します。
3. ホーム画面のアイコンから再起動し、打刻ホームと登録済み従業員が表示されることを確認します。
4. テスト用従業員で出勤・退勤を記録し、管理画面の勤怠履歴へ反映されることを確認します。
5. アプリをもう一度終了・再起動し、記録が残っていることを確認します。
6. 機内モードを解除し、通常運用へ戻します。試験記録が不要な場合は、監査履歴を残す所定の訂正手順で処理します。

Safariのタブで開いただけの確認、開発サーバー、別originでの確認は、納品版のオフライン受入試験にはなりません。

## ロールバック

更新後に打刻や管理機能へ重大な問題が見つかった場合は、次の順で直前の正常版へ戻します。

1. 新しい打刻操作を止め、可能なら現行データのJSONバックアップを作成します。
2. **SafariのWebサイトデータやホーム画面アプリを削除しないでください。** 削除するとIndexedDBの業務データを失うおそれがあります。
3. 直前に動作確認済みのビルド成果物を、同じGitHub Pagesの固定originへ再公開します。
4. iPhoneをネット接続してアプリを開き、更新通知から旧版への切り替えを適用します。
5. 再読み込み後に打刻・履歴表示・データ件数を確認し、続けて上記のオフライン試験を行います。

ロールバックはアプリ本体を戻す操作です。IndexedDBのデータ形式が非互換になった場合は、自己判断でサイトデータを消さず、更新前バックアップを保全したうえで復元可否を確認してください。
