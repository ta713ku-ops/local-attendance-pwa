# Enterprise UI 実装契約

## Context and goals

店舗の打刻を迷わず完了でき、管理者が密度の高い勤怠データを正確に確認できる、清潔で高コントラストな業務画面にする。基盤は `Enterprise` だけを使用し、外部フォントを読み込まずWindowsシステムフォントへ適応する。

## Design tokens and foundations

- `--color-primary: #072c2c`、`--color-accent: #ff5f03`
- `--color-success: #15803d`、`--color-warning: #b45309`、`--color-danger: #b91c1c`
- ページ背景は淡い暖色系グレー、カードは白、本文は `#111827`
- 本文は `"Yu Gothic UI", "Meiryo UI", "Segoe UI", sans-serif`
- 余白は8px基準、主要間隔は16/24/32px。角丸は4pxと8pxだけを使用する
- 境界線を基本とし、影は情報階層が必要な浮遊面だけに限定する
- アニメーションは150ms以内。`prefers-reduced-motion` では無効化する

## Component-level rules

- 打刻名ボタンは高さ72px以上、その他の操作は44px以上。長い氏名は2行まで表示する
- Primaryは確定操作、accentは現在位置や注意喚起、dangerは不可逆・高リスク操作だけに使う
- 入力はラベル、説明、エラーを関連付ける。placeholderをラベル代わりにしない
- 表は見出しを固定し、数値を右揃え、空状態・読込中・失敗状態を専用表示する
- 管理画面は固定幅サイドバーと可変メイン領域。1366x768で横スクロールを発生させない
- 確認ダイアログは対象、結果、取り消し可否を文章で示し、初期フォーカスを安全側へ置く

各操作には `default / hover / focus-visible / active / disabled / loading / error` の該当状態を実装する。

## Accessibility requirements

- WCAG 2.2 AA相当。通常文字4.5:1、大きい文字3:1以上を目標にする
- Tab順は視覚順と一致させ、フォーカスリングは2px以上で背景から識別できる色にする
- 色だけで状態を伝えず、見出し、アイコン、説明文を併用する
- Escapeで閉じられる一時面、Enter/Spaceで操作できるボタン、適切な見出し階層を維持する
- 打刻フローの自動復帰前後はライブリージョンで通知する。管理者画面は時間経過だけでロックせず、「ロックして打刻へ戻る」を選ぶまで操作状態を維持する

## Content and tone

短く、断定的で、次に取る行動が分かる日本語を使う。例: 「打刻は保存されました。バックアップに失敗しました。」。「エラーが発生しました」だけの表示は禁止する。

金額表示には必ず「残業・休日・控除等を含まない30分丸めの参考値」を併記する。

## Anti-patterns

- グラデーション、ガラス表現、過度な影、装飾だけのアニメーションを加えない
- 絵文字を業務アイコンとして使わない
- 危険操作と通常操作を同じ視覚強度にしない
- 横スクロール前提の主要導線、44px未満の主要操作、低コントラストの補助文を作らない

## QA checklist

- 1366x768と1920x1080で主要導線が欠けない
- マウスなしで打刻・PIN・管理ナビゲーションを操作できる
- 長い氏名、0件、読込中、保存失敗、保存済みバックアップ失敗を確認できる
- focus-visible、コントラスト、reduced motion、印刷レイアウトを確認する
